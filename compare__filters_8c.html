Detailed Description

Measure compression ratio and I/O throughput of every lossless NetCDF-4 filter on real GDAS surface data.

This program reads four full-grid fields from the committed sample test/data/gdas_sfc_sample.nc (tmp2m, prate_ave, soilw1 and land, each 1 x 768 x 1536 NC_FLOAT) and rewrites each one with every lossless filter combination available to NetCDF-4: none, deflate levels 1/5/9, szip (NC_SZIP_NN, 32 pixels per block), zstandard levels 1/3/9/19, bzip2 levels 1/9 and LZ4 levels 1/9 — each with the HDF5 shuffle filter off and on. Filters whose plugin is not available are skipped and reported, not failed.

Write time covers nc_create() through nc_close(), including the defines, nc_enddef() and nc_put_var_float(). Read time covers nc_open() through nc_close(), including nc_inq_varid() and nc_get_var_float(). Each configuration is run NREPS times and the minimum is reported; bit-exact round-trip and filter-ID verification happen outside the timed regions. The reported file size is the whole file from stat(), so it includes a few KB of HDF5 metadata — the "none" row shows that overhead.

Output: a CSV file with columns:

field,filter,filter_id,level,shuffle,uncompressed_bytes,file_bytes,ratio,write_s,read_s,write_MBps,read_MBps

and a readable table on stdout, one block per field.

Typical workflow:

ctest -R perf_compare_filters --output-on-failure
# or by hand:
HDF5_PLUGIN_PATH=<plugin dirs> ./compare_filters \
test/data/gdas_sfc_sample.nc compare_filters.csv

Learning Objectives:

  • Compare all lossless NetCDF-4 filters on the same real data
  • See how the shuffle filter changes each compressor's ratio
  • Learn to detect filter availability at run time with nc_inq_filter_avail()
  • Learn to verify a variable's filter pipeline with nc_inq_var_filter_ids()

Key Concepts:

  • Shuffle: reorders bytes so significant bytes of adjacent values group together; usually improves every compressor's ratio at little cost. It is enabled through the shuffle argument of nc_def_var_deflate().
  • Filter availability and plugins: filters other than deflate and szip are HDF5 plugins found on HDF5_PLUGIN_PATH at run time; the program probes each one before running it.
  • Real vs synthetic data: real fields have spatial correlation, missing-value regions and zero-dominated areas that synthetic data lacks, so ratios differ from synthetic benchmarks.
  • Fill-value-heavy fields: soilw1 (ocean = fill) and land (categorical) compress far better than the physical fields.

Key API functions:

  • nc_inq_filter_avail() Check whether a filter ID is usable
  • nc_def_var_deflate() Set deflate level and/or the shuffle filter
  • nc_def_var_szip() Set szip compression
  • nc_def_var_filter() Set zstandard via the generic filter API
  • nc_def_var_bzip2() Set bzip2 (NetCDF-C function)
  • nc_def_var_lz4() Set LZ4 (nep-compress function)
  • nc_inq_var_filter_ids() List a variable's filter pipeline
  • nc_put_var_float() Write a whole variable
  • nc_get_var_float() Read a whole variable

Run one configuration NREPS times and report the minima.

Each repetition calls write_file(), read_file(), verify_file() and memcmp() against the original field; any failure prints the field, filter, level and shuffle to stderr and returns 1. After the loop the file is stat'ed for file_bytes and removed, a CSV row is written to csv and a table row is printed to stdout.

On the first LZ4 run the loaded provider is checked once with nep_check_lz4_provider(), after the first write_file().

Parameters

fieldIndex into FIELDS.
dataOriginal field data, NVALS floats.
bufScratch buffer of NVALS floats for reads.
cFilter configuration.
shuffle1 to enable the shuffle filter, 0 otherwise.
Returns
0 on success, 1 on any error.
