# V1.2.0 Sprint 4: Extended Abstract describing nep-compress

Source: docs/roadmap.md, "V1.2.0 Compression Filter for Meteosat / Sprint 4".

## Goal

Add `docs/nep-compress-abstract.md`, an extended abstract that
describes nep-compress 1.2.0 as the current release, with the same
structure and voice as the NEP abstract. It covers the LZ4, BZIP2 and
JPEG-LS filters, how nep-compress fits with NetCDF-C's built-in
filters, and how to build and install it. It includes the two simple
performance charts, a full description of each, a four-field table
taken from the reference run, and conclusions about which compression
to use. The abstract ships in the `v1.2.0` tag, and the README, the
mainpage and the v1.2.0 release notes link to it. No code, build or
recipe changes.

## Work items

### 1. `docs/nep-compress-abstract.md` (new)

Plain Markdown (GitHub-flavored). No Doxygen commands, no HTML. Image
links are relative to `docs/`: `images/compare_filters_write_simple.png`.
Sections, in this order:

1. `# nep-compress: Fast and Specialized Compression Filters for NetCDF-4`,
   then the line `Edward Hartnett, Intelligent Data Design, Inc.`, a
   blank line, and `Version 1.2.0, October 2026`.
2. `# Abstract`: one paragraph of 150-220 words covering:
   - nep-compress adds HDF5 filter support to NetCDF-C and
     NetCDF-Fortran: LZ4 (ID 32004, plugin built by nep-compress),
     Fortran wrappers for NetCDF-C's BZIP2 (ID 307), and C/Fortran
     functions for EUMETSAT's JPEG-LS (ID 32018, external fcidecomp
     plugin) used for Meteosat Third Generation FCI Level-1c imagery.
   - It uses the `nc_def_var_*`/`nc_inq_var_*` convention, and HDF5
     loads the plugins at run time.
   - The benchmark on four real GDAS surface fields compares every
     lossless NetCDF-4 filter. Headline: LZ4 with shuffle is the fastest
     writer and reader of the compressors in every field (at the
     plotted, shuffle-on settings), and zstd level 1 with shuffle
     matches deflate's ratio at 1.7-4 times its write speed.
   - Builds with CMake, installs through Spack or conda, open source
     (MIT).
3. `# Introduction`:
   - NetCDF-C is maintained by NSF Unidata and is the base of many
     workflows.
   - It has had zstd, bzip2, szip and deflate since 4.9.0, plus
     quantize for lossy compression.
   - Bullets of what nep-compress adds (LZ4; the BZIP2 Fortran API;
     JPEG-LS; the `perf_compare_filters` benchmark).
   - nep-compress was split out of NEP
     (https://github.com/Intelligent-Data-Design-Inc/NEP) so that
     compression can be built without NEP's format readers.
   - "The current version is 1.2.0 (<month> 2026)": requirements
     exactly as in the README "Dependencies" section.
4. `# Compression`. Opening paragraph: filters work on chunked
   NetCDF-4 variables. Plugins are found through `HDF5_PLUGIN_PATH` (or
   HDF5's default plugin directory, as in conda). Readers need the same
   plugin, and there must be exactly one provider per filter ID. Then:
   - `## Filters built into NetCDF-C`: deflate (built into HDF5,
     universally readable), szip, zstd, bzip2, and shuffle as a
     pre-filter. A short table: Filter, HDF5 ID, Provided by, API call.
     Six rows: deflate, szip, zstd, bzip2, LZ4, JPEG-LS. Take the values
     from `docs/mainpage.md`, lines 46-53, without the trade-off
     columns.
   - `## LZ4 - Speed First`:
     - LZ77-family algorithm; nep-compress builds the plugin
       `libh5lz4`.
     - `nc_def_var_lz4(ncid, varid, level)`, levels 1-9 (the
       acceleration parameter, so 9 is slightly faster than 1);
       `nc_inq_var_lz4()`; `nf90_def_var_lz4` / `nf90_inq_var_lz4`.
     - Shuffle is set with `nc_def_var_deflate(ncid, varid, 1, 0, 0)`.
     - `nc_def_var_lz4` returns `NC_ENOFILTER` if the plugin is missing.
     - One C snippet copied from `docs/compression.md`, lines 97-104.
   - `## BZIP2 - Size First`: Burrows-Wheeler. The C functions are
     NetCDF-C's own (since 4.9.0). nep-compress adds the Fortran
     wrappers, the build option and tests. It needs an external 307
     plugin (NetCDF-C's `lib__nch5bzip2`). Levels 1-9 select the
     100-900 KB block size.
   - `## JPEG-LS - Meteosat Imagery`:
     - Why: FCI L1c uses it. Quote the *Earth Observation in Practice*
       passage word for word, with its lead-in line and link, exactly as
       in `docs/compression.md`, lines 47-51.
     - `nc_def_var_jpegls(ncid, varid, near)`: `near` 0 is lossless,
       `near` > 0 is near-lossless (lossy).
     - Types: byte/ubyte/short/ushort, rank 2-3. Define-time validation
       prevents silent raw storage. `nc_inq_var_jpegls` reads the
       13-parameter form in FCI files.
     - It needs the fcidecomp or hdf5plugin provider.
     - It is not in the benchmark, because the benchmark fields are
       float.
5. `# Compression Performance`:

     - **General use:** zstd 1 + shuffle. It matched deflate 1's ratio
       within 0.02 on `tmp2m`, `prate_ave` and `soilw1`, and beat it on
       `land` (87.62 vs 54.67), while writing 1.7-4.0 times faster (394
       vs 235 to 254 vs 63 MB/s) and reading 1.7-2.8 times faster. All
       readers need the zstd plugin.
     - **Portability:** deflate 1 + shuffle, the only one readable with
       no plugin.
     - **Speed:** LZ4 + shuffle was the fastest writer and reader of the
       plotted compressors in every field. Its ratio is 6% (`tmp2m`), 10% (`prate_ave`), 10%
       (`soilw1`) and 53% (`land`) below zstd 1's.
       - On `tmp2m`, `soilw1` and `land` it wrote and read faster than
         the shuffle-only "none" point (`tmp2m` 342 vs 259 MB/s
         write), because less data reaches disk. On `prate_ave`, which
         barely compresses, it was slower (294 vs 367 write, 988 vs
         1188 read). State both.
       - Writing with no filters at all is still faster (`tmp2m`
         938 MB/s, CSV row `none,0,0,0`). State this so the claim is
         not overread.
       - Suited to scratch, checkpoint and read-many data.
     - **Smallest files:** bzip2 1 had the highest ratio in every field,
       but wrote at 13-93 MB/s and read at 28-329 MB/s. zstd 19 +
       shuffle (CSV: `tmp2m` 1.98, written at 7 MB/s, read at 826 MB/s)
       is the better archive choice when the data is read often. This
       matches the mainpage.
     - **Shuffle:** it helps continuous float fields. Without it, LZ4
       did not compress `tmp2m` at all (0.998 vs 1.76 with it). It
       hurts szip on every field, and hurts most filters on `land`. The
       charts show shuffle on only. Refer to the mainpage's full
       comparison for shuffle off.

     - **Caveat:** one machine and one data set. Re-run

   import csv, re

   want = {("none","0"),("deflate","1"),("szip","32"),("zstd","1"),("bzip2","1"),("lz4","9")}
