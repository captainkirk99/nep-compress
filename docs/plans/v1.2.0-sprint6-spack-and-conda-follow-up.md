# V1.2.0 Sprint 6: Spack and Conda Follow-up for the Vendored LZ4 Plugin

Source: docs/roadmap.md, "V1.2.0 Compression Filter for Meteosat / Sprint 6".

## Goal

Spack and conda-forge both start at nep-compress 1.2.0. The open
upstream PRs, spack/spack-packages#7334 and
conda-forge/staged-recipes#35426, are switched from 1.1.0 to the
released 1.2.0 tarball, and 1.0.0 and 1.1.0 are dropped from both
recipes. The conda package no longer conflicts with
`hdf5-external-filter-plugins-lz4`, because both plugins now use the
standard 32004 encoding. The plan docs, README and refine-roadmap
skill describe the result and the correct upstream Spack style
checks.

## Decisions

| Topic | Decision |
|---|---|
| Older releases | Spack and conda start at 1.2.0. Remove `1.1.0` from the Spack recipe; the staged recipe is generated for 1.2.0. Neither will ever list 1.0.0 or 1.1.0. (Ed) |
| conda `run_constraints` | Drop `hdf5-external-filter-plugins-lz4 <0.0.0a0`. Both plugins now write and read the same 32004 encoding, and their file names differ (`libh5lz4_nepcompress.so` vs `libh5lz4.so`), so they can share an environment. (Ed: 1a) |
| Spack PR #7334 | Add a new commit on `nep-compress-new-package`; no amend or force-push. Upstream squash-merges, so the PR still lands as one commit. (Ed: 2a) |
| Checkout recipe version | `conda/recipe/recipe.yaml` becomes `version: "1.3.0.dev0"`. `make_staged_recipe.py` replaces whatever quoted `version:` line is in `context:` instead of a hard-coded string. CMake stays `VERSION 1.2.0` until 1.3.0 work starts. (Ed: 3a) |
| Skill fix | `.devin/skills/refine-roadmap/SKILL.md` stops telling plans to run `spack style` and uses upstream's ruff + vermin checks. (Ed: 4a) |
| License | Unchanged: `license("MIT")` in Spack, `license: MIT` and `license_file: LICENSE` in conda. No license work this sprint. (Ed) |
| Commit messages and PR text | No mention of Devin (AGENTS.md). |
