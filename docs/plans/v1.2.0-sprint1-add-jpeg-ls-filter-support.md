# V1.2.0 Sprint 1: Add JPEG-LS Filter Support

Source: `docs/roadmap.md`, "V1.2.0 Compression Filter for Meteosat / Sprint 1".

## Goal

nep-compress supports the EUMETSAT JPEG-LS filter (HDF5 ID 32018,
"FCIDECOMP", `H5ZJPEGLS`). This is the filter used for Meteosat Third
Generation FCI Level-1c imagery. It works the same way as BZIP2: an
external plugin does the compression, and nep-compress provides C and
Fortran functions to define and inquire the filter, an opt-in build
option with a configure-time plugin probe, tests, CI coverage and
documentation. The define function rejects types, ranks and chunk
shapes that the plugin cannot compress, so data is never silently
stored uncompressed. It also supports JPEG-LS near-lossless mode, which
is clearly documented as lossy. The book passage from *Earth
Observation in Practice* that motivated this sprint is kept word for
word in the compression guide and in the v1.2.0 release notes.

## Decisions

| Topic | Decision |
| --- | --- |
| Approach | Use an external plugin, as with BZIP2. nep-compress does **not** build a JPEG-LS plugin. It adds `nc_def_var_jpegls` / `nc_inq_var_jpegls` (C, in `libnepcompress`) and `nf90_def_var_jpegls` / `nf90_inq_var_jpegls` (Fortran). They are built with the new `NEPCOMPRESS_BUILD_JPEGLS` (default OFF) and need `NEPCOMPRESS_JPEGLS_PLUGIN_DIR` to point to a directory with one 32018 provider (EUMETSAT fcidecomp `libH5Zjpegls.so` or hdf5plugin `libh5fcidecomp.so`). (Ed: 1a) |
| Near-lossless | `nc_def_var_jpegls(int ncid, int varid, int near)`. `near = 0` is lossless. `near > 0` is JPEG-LS near-lossless (lossy, every decoded value within `near` of the original). Valid range: 0-127 for 1-byte types and 0-255 for 2-byte types (the JPEG-LS limit `min(255, MAXVAL/2)`). Anything outside the range returns `NC_EINVAL`. (Ed: 2b) |
| Validation | `nc_def_var_jpegls` returns `NC_EBADTYPE` unless the type is `NC_BYTE`, `NC_UBYTE`, `NC_SHORT` or `NC_USHORT`. It returns `NC_EINVAL` if the rank is not 2 or 3, or if the chunk shape would make the plugin's `can_apply` fail. (Ed: 3a) |
| Default chunking | If the variable is not yet chunked, `nc_def_var_jpegls` calls `nc_def_var_chunking(ncid, varid, NC_CHUNKED, NULL)` so NetCDF-C's default chunk sizes are used. It then checks the resulting chunks. If that check fails, the variable stays chunked with no filter; this is documented. |
| Check order | Plugin availability first (`NC_ENOFILTER`), as `nc_def_var_lz4` and NetCDF-C's `nc_def_var_bzip2` do. Then type, rank, `near` and chunks. |
| Inquiry | `nc_inq_var_jpegls(int ncid, int varid, int *jpeglsp, int *nearp)`. It works like `nc_inq_var_lz4`: it searches the whole pipeline, counts parameters first and does not need the plugin. It accepts 0, 9 or 13 parameters, and any other count is `NC_EFILTER`. |
| Test data | Only synthetic data generated by the tests. No EUMETSAT data is committed or downloaded. (Ed: 4a) |
| Book quote | Both quoted paragraphs, word for word with attribution, go into a new JPEG-LS section in `docs/compression.md` and into the new `docs/release-notes-v1.2.0.md`. The mainpage comparison table gets a JPEG-LS row. (Ed: 5a) |
| Plugin path rule | The same as for the other filters: JPEG-LS tests get only `NEPCOMPRESS_JPEGLS_PLUGIN_DIR`, and that directory must hold exactly one 32018 provider. |
| Version / ABI | `project(... VERSION 1.2.0)`. Two new exported C symbols are an additive change, so `SOVERSION` stays 1. |
| Roadmap heading | Correct "Mereosat" to "Meteosat". |

- Filter facts (registered list
  `HDFGroup/hdf5_plugins/docs/RegisteredFilterPlugins.md`, and
  fcidecomp source `gaubert/fcidecomp-open-repo`, Apache-2.0,
  `src/fcidecomp/fcicomp-H5Zjpegls`):
  - **The ID is 32018 ("FCIDECOMP").** ID 32012 is a different,
    older CharLS filter.
  - `H5Zjpegls.h` defines `H5Z_FILTER_JPEGLS 32018`. Its user
    parameters are a 9-element `jls_parameters_t`: `bit_per_sample`,
    `components`, `ilv`, `near`, `maxval`, `t1`, `t2`, `t3`, `reset`.
    All zeros means defaults and lossless.
  - `set_local` reads up to 9 user parameters and rewrites the filter
    with `H5Z_FLAG_OPTIONAL` and 13 parameters: `dataBytes`,
    `dims[3]` (components, lines, samples) and then the 9 user values.
    So `near` is at index 3 in the 9-parameter form and at index 7 in
    the 13-parameter form.
  - `can_apply` requires an integer type of 1 or 2 bytes and a chunk
    rank of 2 or 3. In rank 3, the first chunk dimension is the
    component count and must be 1-4. Lines and samples must each be at
    most 65535, and there must be at least 16 pixels per chunk.
  - The encoder returns 0, so the chunk is stored raw, when compression
    does not shrink the data. The plugin prints its own `ERROR:` and
    `WARNING:` lines to stderr.
  - It uses `malloc`/`free` on HDF5 filter buffers, not
    `H5allocate_memory`. This worked with HDF5 2.1.1 and is outside
    our control.
- Probes run on the development machine (NetCDF-C 4.10.2-development,
  HDF5 2.1.1), using `libh5fcidecomp.so` from the hdf5plugin 7.1.0
  wheel alone in one directory:
  - `nc_inq_filter_avail(ncid, 32018)` returns `NC_NOERR`. With no
    plugin it returns `NC_ENOFILTER` (-136).
  - A 100×120 `NC_USHORT` variable with chunks `{1,100,120}` and
    `nc_def_var_filter(..., 32018, 9, zeros)` round-trips bit-exactly.
    The dataset storage is 1887 bytes (12.7:1).
  - In define mode, and after the write before close,
    `nc_inq_var_filter_info` reports the 9 parameters as given. After
    reopening it reports 13: `2 1 100 120 16 1 0 0 0 0 0 0 0`.
    Defining with 0 parameters also works, and reports 0 parameters
    until reopen.
  - `NC_BYTE`, `NC_UBYTE`, `NC_SHORT` (with negative values) and
    `NC_USHORT` round-trip losslessly with `near = 0`.
  - With `NC_INT` and `NC_FLOAT`, `nc_def_var_filter`, `nc_enddef`,
    `nc_put_var` and `nc_close` all return `NC_NOERR`. The plugin
    prints errors, and the data is stored **uncompressed**. This is the
    reason for decision 3a.
  - `near = 2` on ushort is lossy (the data does not compare equal).
    `near = 255` works on ushort and `near = 256` falls back silently
    to uncompressed. On ubyte, CharLS accepted up to 255 and fell back
    at 256. The plan uses the spec limit of 127 for 1-byte types
    anyway.
  - Rank-3 chunks `{1|2|4, 100, 120}` with a 4×100×120 ushort variable
    all round-trip losslessly and compress about 10.5:1.
  - Shuffle followed by 32018 round-trips, and `nc_inq_var_filter_ids`
    lists `2, 32018`.
- Real file: the fcidecomp test file
  `W_XX-EUMETSAT-Darmstadt,IMG+SAT,MTI1+FCI-1C-RRAD-HRFI-FD--CHK-BODY--DIS-NC4E_C_EUMT_20260507092518_IDPFI_OPE_20260507092052_20260507092132_N_JLS_O_0057_0007.nc`
  (16,674,100 bytes, git LFS). It has global
  `special_compression = "JLS"`, `_NCProperties` netcdf 4.7.4 / hdf5
  1.12.2, and 2-D `ushort effective_radiance`, `ushort index_map` and
  `ubyte pixel_quality` in channel groups. A typical stored filter is
  `_Filter = "32018,2,1,601,22272,16,1,0,0,0,0,0,0,0"` (13 parameters,
  `near` = 0). `nccopy -F none` with the hdf5plugin plugin decodes it
  to 168 MB in 0.9 s. Without the plugin `nccopy` fails. The repository
  also has an EUMETSAT_PROPRIETARY licence file, so this data is not
  used here (decision 4a).
- CI availability: the hdf5plugin 7.1.0 wheel ships
  `hdf5plugin/plugins/libh5fcidecomp.so`, which exports
  `H5PLget_plugin_type` and `H5PLget_plugin_info`. CI already loads
  bzip2 and zstd from that directory through `HDF5_PLUGIN_PATH`. That

- Local tools: CMake 3.28.3, Doxygen 1.9.8, GCC 13.3. `libcharls2` is

- Declare, unconditionally like LZ4, with full Doxygen blocks:

  ```c
  int nc_def_var_jpegls(int ncid, int varid, int near);
  int nc_inq_var_jpegls(int ncid, int varid, int *jpeglsp, int *nearp);
  ```

  - `nc_def_var_jpegls` doc:
    - Call it in define mode, before data is written.
    - Allowed types are `NC_BYTE`, `NC_UBYTE`, `NC_SHORT` and
      `NC_USHORT`, and the rank must be 2 or 3.
    - If the variable is not chunked yet, NetCDF-C's default chunk
      sizes are applied first.
    - The chunks must satisfy the plugin: in rank 3 the first chunk
      dimension is 1-4 (the plugin treats it as image components), the
      last two chunk dimensions are each at most 65535, and there must
      be at least 16 pixels per chunk.
    - Changing the chunking after this call to a shape outside these
      limits makes HDF5 store the data uncompressed without an error.
    - `@param near`: 0 for lossless. 1-127 (1-byte types) or 1-255
      (2-byte types) for near-lossless (lossy) compression, where every
      value is within `near` of the original.
    - `@return`: `NC_NOERR`; `NC_ENOFILTER` if the plugin is
      unavailable (checked first); `NC_EBADTYPE` for an unsupported
      type; `NC_EINVAL` for a bad rank, `near` or chunk shape (after a
      chunk-shape `NC_EINVAL` the variable may have been switched to
      chunked storage); or another NetCDF error.
    - `@author`.
  - `nc_inq_var_jpegls` doc:
    - It searches the whole pipeline and does not need the plugin.
    - `*jpeglsp` is set to 0 at the start, and to 1 when filter 32018
      is present.
    - `*nearp` is written when 32018 is present with 0, 9 or 13
      parameters: 0 for 0 parameters, parameter 3 for the 9-value
      user form (define mode), parameter 7 for the 13-value form that
      the plugin stores in files (including EUMETSAT FCI files).
    - It returns `NC_EFILTER` (with `*jpeglsp = 1`) for any other
      count, or another NetCDF error.
    - `@author`.

`src/nep_compress.c`:

- `@file` brief: "Implementation of the nep-compress LZ4 and JPEG-LS
  filter API."
- Add a `#ifdef NEPCOMPRESS_BUILD_JPEGLS` block after the LZ4 block.
  Give every macro and the static helper a Doxygen block (the static
  helper also gets `@author`) so the docs build stays warning-free:

  ```c
  /** Number of user parameters for filter 32018 (jls_parameters_t). */
  #define JPEGLS_USER_NPARAMS 9
  /** Number of parameters filter 32018 stores in the file after set_local. */
  #define JPEGLS_STORED_NPARAMS 13
  /** Index of the near-lossless bound in the user parameter form. */
  #define JPEGLS_NEAR_USER 3
  /** Index of the near-lossless bound in the stored parameter form. */
  #define JPEGLS_NEAR_STORED 7
  /** Largest chunk line or sample count accepted by the plugin. */
  #define JPEGLS_MAX_XY 65535
  /** Smallest number of pixels per chunk accepted by the plugin. */
  #define JPEGLS_MIN_PIXELS 16
  /** Largest number of image components (first chunk dimension, rank 3). */
  #define JPEGLS_MAX_COMPONENTS 4

  static int
  jpegls_chunks_ok(int ndims, const size_t *chunks)
  {
      size_t lines = chunks[ndims - 2], samples = chunks[ndims - 1];

      if (ndims == 3 && (chunks[0] < 1 || chunks[0] > JPEGLS_MAX_COMPONENTS))
          return 0;
      return lines <= JPEGLS_MAX_XY && samples <= JPEGLS_MAX_XY &&
             lines * samples >= JPEGLS_MIN_PIXELS;
  }

  int
  nc_def_var_jpegls(int ncid, int varid, int near)
  {
      unsigned int params[JPEGLS_USER_NPARAMS] = {0};
      size_t chunks[3];
      nc_type xtype;
      int ndims, storage, max_near, ret;

      if ((ret = nc_inq_filter_avail(ncid, JPEGLS_ID)))
          return ret;
      if ((ret = nc_inq_var(ncid, varid, NULL, &xtype, &ndims, NULL, NULL)))
          return ret;
      switch (xtype)
      {
      case NC_BYTE:
      case NC_UBYTE:
          max_near = 127;
          break;
      case NC_SHORT:
      case NC_USHORT:
          max_near = 255;
          break;
      default:
          return NC_EBADTYPE;
      }
      if (ndims != 2 && ndims != 3)
          return NC_EINVAL;
      if (near < 0 || near > max_near)
          return NC_EINVAL;
      if ((ret = nc_inq_var_chunking(ncid, varid, &storage, NULL)))
          return ret;
      if (storage != NC_CHUNKED &&
          (ret = nc_def_var_chunking(ncid, varid, NC_CHUNKED, NULL)))
          return ret;
      if ((ret = nc_inq_var_chunking(ncid, varid, &storage, chunks)))
          return ret;
      if (!jpegls_chunks_ok(ndims, chunks))
          return NC_EINVAL;
      params[JPEGLS_NEAR_USER] = (unsigned int)near;
      return nc_def_var_filter(ncid, varid, JPEGLS_ID, JPEGLS_USER_NPARAMS, params);
  }

  int
  nc_inq_var_jpegls(int ncid, int varid, int *jpeglsp, int *nearp)
  {
      unsigned int params[JPEGLS_STORED_NPARAMS];
      size_t nparams;
      int ret;

      if (jpeglsp)
          *jpeglsp = 0;
      ret = nc_inq_var_filter_info(ncid, varid, JPEGLS_ID, &nparams, NULL);
      if (ret == NC_ENOFILTER)
          return NC_NOERR;
      if (ret)
          return ret;
      if (jpeglsp)
          *jpeglsp = 1;
      if (nparams == 0)
      {
          if (nearp)
              *nearp = 0;
          return NC_NOERR;
      }
      if (nparams != JPEGLS_USER_NPARAMS && nparams != JPEGLS_STORED_NPARAMS)
          return NC_EFILTER;
      if ((ret = nc_inq_var_filter_info(ncid, varid, JPEGLS_ID, &nparams, params)))
          return ret;
      if (nearp)
          *nearp = (int)params[nparams == JPEGLS_USER_NPARAMS ?
                               JPEGLS_NEAR_USER : JPEGLS_NEAR_STORED];
      return NC_NOERR;
  }
  ```

- Tricky cases:

  - `nc_inq_var_chunking` fills `chunks` only when storage is

  - The `chunks[3]` buffer is safe because the rank has already been

### 4. Tests

All test code uses plain comments with
`Author: Edward Hartnett, Intelligent Data Design, Inc.` and no Doxygen
markup.

**New `test/tst_jpegls.c`** (ctest `tst_jpegls`), using the
`nep_test.h` macros and `int main(int argc, char **argv)`. Constants:
`NY 100`, `NX 120`. Variable name `radiance`, dimensions `y`, `x` (and
`t` for rank 3). Helper `static int storage_ok(const char *path, const
char *var, size_t raw_bytes)`: it opens the file with HDF5
(`H5Fopen(path, H5F_ACC_RDONLY, H5P_DEFAULT)`, `H5Dopen2`), and returns
0 when `H5Dget_storage_size` is less than `raw_bytes / 2`, 1 otherwise,
closing all HDF5 IDs. This catches the plugin's silent raw fallback.
Data patterns, for row `y` and column `x`:

| Type | Value |
| --- | --- |
| `NC_USHORT` | `(x * 7 + y * 3) & 0x0fff` |
| `NC_SHORT` | `(x * 7 + y * 3) % 3000 - 1500` |
| `NC_UBYTE` | `(x + y) % 200` |
| `NC_BYTE` | `(x + y) % 100 - 50` |

Cases (each prints a `*** Checking ...` line and calls
`SUMMARIZE_ERR`):

1. **No filter:** after `nc_def_var`, `nc_inq_var_jpegls` gives
   `NC_NOERR` and has = 0. Calls with NULL for one or both pointers
   return `NC_NOERR`.
2. **Lossless, each type** (`NC_USHORT`, `NC_SHORT`, `NC_UBYTE`,
   `NC_BYTE`), 2-D, no explicit chunking (this exercises the default
   chunking path):
   - `nc_def_var_jpegls(..., 0)`.
   - In define mode: has 1, near 0, and `nc_inq_var_filter_info`
     gives 9 parameters.
   - Write and close, then check `storage_ok`.
   - Reopen: has 1, near 0, `nc_inq_var_filter_info` gives 13
     parameters with `params[0]` equal to the type size (1 or 2), and
     the data matches exactly.
   - The `NC_USHORT` file is named `tst_jpegls_lossless.nc` and is kept
     for the fixture test (item 5). Other files get per-case names.
3. **Near-lossless:**
   - `NC_USHORT` with `near = 2`: has 1 and near 2 before and after
     reopen. Every `abs(in - out) <= 2`, and at least one value
     differs (this proves lossy mode was really applied). Check
     `storage_ok`.
   - `NC_UBYTE` with `near = 127` and `NC_USHORT` with `near = 255`:
     `NC_NOERR`, and after reopen near is 127 / 255.
4. **Rank 3:** dims `t = 4`, `y`, `x`, `NC_USHORT`. Two variables,
   with chunks `{1, NY, NX}` and `{4, NY, NX}`. Both get near 0. Both
   round-trip exactly and pass `storage_ok`.
5. **After shuffle:** `nc_def_var_deflate(ncid, varid, 1, 0, 0)`, then
   `nc_def_var_jpegls(..., 0)`. The inquiry finds it (has 1, near 0)
   before and after reopen, and the data round-trips. No storage check,
   because shuffle breaks up the image structure.
6. **Rejected arguments** (define only, then `nc_abort`). After each
   call, `nc_inq_var_jpegls` reports has 0:
   - `NC_INT`, `NC_FLOAT` and `NC_CHAR` 2-D variables: `NC_EBADTYPE`.

> EUMETSAT disseminates FCI Level-1c imagery with stronger lossless compression based on the JPEG-LS standard through the CharLS library. JPEG-LS is implemented as a custom HDF5 filter (`H5ZJPEGLS`), not built into standard NetCDF-4 or HDF5 installations. ## Out of scope

- A nep-compress-built JPEG-LS/CharLS plugin. Not planned, because the
  external fcidecomp plugin defines the format (decision 1a).
- Committing or downloading real EUMETSAT FCI data, or an automated
  real-file test. Not planned (decision 4a). The manual check in
  Verification step 5 covers it once.
- JPEG-LS rows in `perf_compare_filters`. The GDAS sample is float,
  which JPEG-LS cannot compress. Not planned for v1.2.0. A later
  sprint could add integer imagery.
- Exposing JPEG-LS parameters other than `near` (`bit_per_sample`,
  `ilv`, preset `maxval`/`t1`-`t3`/`reset`). Not planned.
- Rewriting the chunk shape on the user's behalf beyond applying
  NetCDF-C defaults. Not planned.
- Windows/macOS plugin naming and path separators. Unix-only, like the
  rest of the test suite.
