# V1.1.0 Sprint 1: Documentation

Source: `docs/roadmap.md`, "V1.1.0 - Documentation / Sprint 1".

## Goal

Publish complete Doxygen documentation for nep-compress on GitHub Pages,
rebuilt on demand and after every release, with a mainpage that
describes the project and compares the compression filters available to
NetCDF-4 users. Bring author attribution and the README up to the
standard set in the roadmap.

## Decisions

| Topic | Decision |
| --- | --- |
| Deployment | Push generated HTML to a `gh-pages` branch. Pages source is the `gh-pages` branch, root. |
| Triggers | `workflow_dispatch` (user-run) and `release: types: [published]` (automatic after every release). |
| Build integration | CMake option `NEPCOMPRESS_BUILD_DOCS` (default OFF) and a `docs` target generated from `docs/Doxyfile.in`. |
| Strictness | Undocumented or badly documented code fails the docs build in CI (`WARN_AS_ERROR`). A docs-check job is added to `ci.yml` so problems surface on every push and PR, not just at release time. |
| Filter comparison | Qualitative table and prose, with links to the existing LZ4/BZIP2 results in `examples/performance`. No new benchmarks this sprint (Sprint 3 does that). |
| README books | Short "Books" section after the intro. Covers side by side in an HTML table at `width="200"`, each linked to a short `amazon.com/dp/<ASIN>` URL with the tracking parameters removed. The covers also appear on the Doxygen mainpage. |

  enabled for `captainkirk99/nep-compress` (the API returns 404).

  `Edward Hartnett, Intelligent Data Design, Inc.`

  (24.04) provides the same Doxygen version through apt.

## Work items

### 1. Doxygen configuration and CMake target

- Add `docs/Doxyfile.in`, configured by CMake:
  - `PROJECT_NAME = nep-compress`, `PROJECT_NUMBER = @PROJECT_VERSION@`,
    `PROJECT_BRIEF` = one-line description.
  - `INPUT`: `docs/mainpage.md`, `docs/compression.md`,
    `plugins/LZ4_HDF5_format.md`, `include`, `src`, `fsrc`, `plugins`,
    `examples/performance`. `test/` is not a Doxygen input.
  - `FILE_PATTERNS = *.h *.c *.F90 *.f90 *.md`;
    `EXTENSION_MAPPING = F90=FortranFree f90=FortranFree`.
  - `EXCLUDE_PATTERNS = */build/*`. Exclude `README.md` (the mainpage
    is separate).
  - `ENABLE_PREPROCESSING = YES`, `MACRO_EXPANSION = YES`,
    `PREDEFINED = NEPCOMPRESS_BUILD_LZ4 NEPCOMPRESS_BUILD_BZIP2`, so both
    filters' APIs are documented however the library was configured.
  - `IMAGE_PATH = docs` (book covers), `EXTRACT_STATIC = YES`,
    `EXTRACT_ALL = NO`, `WARN_IF_UNDOCUMENTED = YES`,
    `WARN_NO_PARAMDOC = YES`,
    `WARN_AS_ERROR = @NEPCOMPRESS_DOCS_WARN_AS_ERROR@`,
    `GENERATE_LATEX = NO`, `HAVE_DOT = YES`, `OUTPUT_DIRECTORY` under
    the build tree.
- `CMakeLists.txt`:
  - `option(NEPCOMPRESS_BUILD_DOCS "Build Doxygen HTML documentation" OFF)`
  - Cache var `NEPCOMPRESS_DOCS_WARN_AS_ERROR` (default `NO`; CI passes
    `FAIL_ON_WARNINGS`).
  - When ON: add a `docs` custom target (not in `ALL`) that runs
    `cmake -P docs/build_docs.cmake`.
  - `docs/build_docs.cmake` is the single docs entry point. It finds
    `doxygen`, configures `Doxyfile.in` with `@ONLY`, and runs Doxygen.
    The CI and deploy workflows call it directly, so they do not need
    NetCDF, HDF5, or Fortran installed.
- Add `NEPCOMPRESS_BUILD_DOCS` to the README options table.

### 2. Doxygen mainpage (`docs/mainpage.md`)

Start the file with `@mainpage nep-compress` (or `{#mainpage}`). Sections:

1. **What nep-compress is**: LZ4 and BZIP2 filters for NetCDF-4/HDF5,
   C and Fortran APIs, its relationship to NEP, and what is and is not
   built (the LZ4 plugin is built; BZIP2 needs an external ID 307 plugin).
2. **Provided filters**: links to `nc_def_var_lz4`, `nc_inq_var_lz4`,
   `nc_def_var_bzip2`, `nc_inq_var_bzip2`, the Fortran equivalents, the
   LZ4 plugin file, the [compression guide](compression.md), and the LZ4
   on-disk format page.
3. **Filter comparison**. A table with these columns: filter, HDF5 ID,
   provided by, plugin required, API call, parameters/levels, typical
   trade-off (speed vs. ratio), lossless. Rows:
   - deflate/zlib (ID 1, built into HDF5, `nc_def_var_deflate`, 0-9)
   - szip (ID 4, HDF5 with libaec/szip, `nc_def_var_szip`, options mask
     and pixels_per_block; not combinable with deflate)
   - zstandard (ID 32015, NetCDF-C plugin `lib__nch5zstd`,
     `nc_def_var_zstandard`; this call silently does nothing when
     NetCDF-C was built without zstd, so check `NC_HAS_ZSTD`)
   - bzip2 (ID 307, external plugin, nep-compress or NetCDF-C
     `nc_def_var_bzip2`, 1-9)
   - LZ4 (ID 32004, nep-compress plugin, `nc_def_var_lz4`, 1-9)
   - Separate short subsection on pre-filters that are not compressors
     but affect the result: shuffle (ID 2) and quantize
     (`nc_def_var_quantize`), with fletcher32 mentioned as a checksum.
   - Prose guidance: when to pick speed (LZ4), ratio (BZIP2, high zstd
     levels), or portability (deflate: every reader has it). Point out
     that readers need the same plugin on `HDF5_PLUGIN_PATH`.
   - Link to `examples/performance/README.md` and the CSV results. State
     that measured comparisons across all filters are coming in a later
     release (Sprint 3), rather than making up numbers.
   - Check every ID and API claim against `.devin/skills/netcdf/SKILL.md`
     and the installed `netcdf_filter.h`.
4. **Books**: both covers and links (same as README).
5. **Author**: Edward Hartnett, Intelligent Data Design, Inc.

### 3. API documentation

Use this author string everywhere except `plugins/H5Zlz4.c` (below):
`@author Edward Hartnett, Intelligent Data Design, Inc.`

- `include/nep_compress.h`: `@file` block; document `BZIP2_ID` and
  `LZ4_ID`. Full doc blocks for the 4 public functions, with `@param`
  for every argument (including NULL-allowed outputs), `@return` listing
  `NC_NOERR`, `NC_EINVAL` (bad level), `NC_EFILTER` (plugin unavailable),
  and other NetCDF errors, plus `@author`. The header is the installed, user-facing file, so the full docs go
  there.
- `src/nep_compress.c`: `@file` block. Document static `define_filter`
  (`@internal`, params, return, author). Public definitions get no
  second full block, which would create duplicates. Each gets a
  one-line `/** @copydoc ... */` or nothing, whichever Doxygen 1.9.8
  accepts without warnings.
- `fsrc/nep_compress.F90`: `!>` docs for the module and all 4 functions
  (`@param`, `@return`, `@author`). Confirm
  that the `#ifdef` public lists still parse with `PREDEFINED` set.
- `plugins/H5Zlz4.c`, `plugins/lz4_config.h`: `@file` and docs for
  `H5Z_filter_lz4`, the filter class struct, and registration functions.
  **Attribution rule:** `H5Zlz4.c` is adapted upstream code of unknown
  origin. Every `@file` and function block in it uses
  `@author Unknown Programmer`, not Edward Hartnett. `lz4_config.h` is a
  nep-compress shim and uses the normal author string.
