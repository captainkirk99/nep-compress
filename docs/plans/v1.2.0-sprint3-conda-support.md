# V1.2.0 Sprint 3: Conda Support

Source: `docs/roadmap.md`, "V1.2.0 Compression Filter for Meteosat / Sprint 3".

## Goal

nep-compress can be installed from conda-forge as the package
`nep-compress`. In any conda environment, HDF5 picks up its LZ4 plugin
with no environment variable. The recipe lives in this repository as a
rattler-build `recipe.yaml`. A new CI workflow builds it from the
checkout against current conda-forge pinnings, runs the full CTest
suite inside the conda build, runs the package tests, and lints the
recipe that is submitted. The 1.1.0 recipe is submitted to
`conda-forge/staged-recipes`, and `docs/conda-plan.md` documents
submission and upkeep the same way `docs/spack-plan.md` does for
Spack.

## Decisions

| Topic | Decision |
| --- | --- |
| Version submitted | 1.1.0 (the existing `v1.1.0` tarball). Once the feedstock exists, conda-forge's autotick bot proposes 1.2.0 after the tag. (Ed: 1a) |
| Plugin location | `build.sh` moves the installed `lib/plugin/libh5lz4.so` to `$PREFIX/lib/hdf5/plugin/libh5lz4_nepcompress.so`, which is conda-forge HDF5's default plugin directory, and removes `lib/plugin`. The recipe adds `run_constraints: hdf5-external-filter-plugins-lz4 <0.0.0a0`, so the two 32004 providers can never be in one environment. No CMake change. (Ed: 2a) |
| Platforms | linux-64 only (`skip: not linux`). macOS is added later in the feedstock. (Ed: 3a) |
| Recipe home and CI | The source of truth is `conda/recipe/recipe.yaml` + `conda/recipe/build.sh`, building the checkout (`source: path: ../..`). `conda/make_staged_recipe.py` generates the staged-recipes copy (tarball `source`, release version), so the two cannot drift. A new `.github/workflows/conda.yml` builds with rattler-build and lints the generated copy with conda-smithy. Also new: `docs/conda-plan.md`. (Ed: 4a) |
| Maintainers | `recipe-maintainers: [edhartnett, captainkirk99]`. (Ed: 5c) |
| Package shape | One output `nep-compress` containing `libnepcompress`, `libnepcompressf` and the Fortran module, the header, the CMake package files and the LZ4 plugin. Build options: LZ4 ON, BZIP2 ON, Fortran ON. JPEG-LS is not set (default OFF; 1.1.0 does not have it). |
| MPI | Host pins `hdf5 * nompi_*` and `libnetcdf * nompi_*`. conda-forge's nompi `run_exports` do not constrain the MPI variant, so the package also installs into MPI environments. No mpi variants. |
| Pinnings | Builds (CI and local) use conda-forge's `conda_build_config.yaml` from `conda-forge-pinning-feedstock`, passed to rattler-build with `-m`. |
| Submission | The staged-recipes fork and PR are created only after Ed's go-ahead, because they are external actions. Both maintainers confirm in the PR, as conda-forge requires. |
| Spack | Unaffected: no CMake option, dependency or install-layout change in nep-compress. |

## Work items

### 1. Recipe

New `conda/recipe/recipe.yaml`:

```yaml
schema_version: 1

context:
  name: nep-compress
  version: "1.2.0.dev0"

package:
  name: ${{ name }}
  version: ${{ version }}

# BEGIN source
source:
  path: ../..
# END source

build:
  number: 0
  skip:
    - not linux

requirements:
  build:
    - ${{ compiler('c') }}
    - ${{ stdlib('c') }}
    - ${{ compiler('fortran') }}
    - cmake
    - ninja
    - pkg-config
  host:
    - libnetcdf >=4.10.1
    - libnetcdf * nompi_*
    - netcdf-fortran
    - netcdf-fortran * nompi_*
    - hdf5
    - hdf5 * nompi_*
    - lz4-c
  run_constraints:
    - hdf5-external-filter-plugins-lz4 <0.0.0a0

tests:
  - script:
      - test -f $PREFIX/lib/libnepcompress${SHLIB_EXT}
      - test -f $PREFIX/lib/libnepcompressf${SHLIB_EXT}
      - test -f $PREFIX/include/nep_compress.h
      - test -f $PREFIX/lib/cmake/NEPCompress/NEPCompressConfig.cmake
      - test -f $PREFIX/lib/hdf5/plugin/libh5lz4_nepcompress.so
      - test ! -e $PREFIX/lib/plugin
      - cmake -S test/consumer -B consumer-build -G Ninja -DCMAKE_PREFIX_PATH=$PREFIX
      - cmake --build consumer-build
      - ./consumer-build/consumer_c
      - ./consumer-build/consumer_fortran
    files:
      source:
        - test/consumer/
    requirements:
      run:
        - ${{ compiler('c') }}
        - ${{ compiler('fortran') }}
        - cmake
        - ninja
        - pkg-config

about:
  homepage: https://captainkirk99.github.io/nep-compress/
  repository: https://github.com/captainkirk99/nep-compress
  documentation: https://captainkirk99.github.io/nep-compress/
  license: MIT
  license_file: LICENSE
  summary: Additional compression filters (LZ4 plugin, BZIP2 Fortran API) for NetCDF-4/HDF5
  description: |
    nep-compress provides an LZ4 HDF5 filter plugin (ID 32004) with C and
    Fortran APIs, and Fortran wrappers for NetCDF-C's BZIP2 filter. The LZ4
```

New `conda/recipe/build.sh` (mode 0755):

```bash
#!/bin/bash
set -euxo pipefail

plugins="${PREFIX}/lib/hdf5/plugin"

cmake -S . -B build -G Ninja ${CMAKE_ARGS} \
  -DCMAKE_INSTALL_LIBDIR=lib \
  -DHDF5_ROOT="${PREFIX}" \
  -DBUILD_TESTING=ON \
  -DNEPCOMPRESS_BUILD_LZ4=ON \
  -DNEPCOMPRESS_BUILD_BZIP2=ON \
  -DNEPCOMPRESS_ENABLE_FORTRAN=ON \
  -DNEPCOMPRESS_BZIP2_PLUGIN_DIR="${plugins}" \
  -DNEPCOMPRESS_ZSTD_PLUGIN_DIR="${plugins}"
cmake --build build --parallel "${CPU_COUNT}"
ctest --test-dir build --output-on-failure --no-tests=error --parallel "${CPU_COUNT}"
cmake --install build

mkdir -p "${plugins}"
mv "${PREFIX}/lib/plugin/libh5lz4.so" "${plugins}/libh5lz4_nepcompress.so"
rmdir "${PREFIX}/lib/plugin"
```

Tricky cases:
- `source: path: ../..` is relative to `conda/recipe/`. rattler-build
  applies `.gitignore` to path sources by default, so local `build*/`
  directories and Spack artifacts are left out. Do not turn that off.
- The `# BEGIN source` / `# END source` markers and the
  `version: "1.2.0.dev0"` line are what `make_staged_recipe.py`
  replaces (item 2). Keep them exactly as written.
- The host `$PREFIX/lib/hdf5/plugin` contains only libnetcdf's
  plugins, so it meets the one-provider-per-ID rule for 307 and 32015.
  libnetcdf is 4.10.1, so `perf_compare_filters` runs (about 60 s).
- Do not pass `NEPCOMPRESS_BUILD_JPEGLS`. It does not exist in 1.1.0,
  and an unused variable would produce a CMake warning.
- The `libnetcdf >=4.10.1` host line is needed for 1.1.0 and is
  harmless for `main`.
- `run_exports` from `libnetcdf`, `netcdf-fortran`, `hdf5` and `lz4-c`
  provide the run requirements. Do not list them under `run`.
- The test runs `consumer_fortran` unconditionally, because the
  package always has Fortran. The 1.1.0 consumer requires a Fortran
  compiler, which the test requirements provide.

### 2. Staged-recipe generator

New `conda/make_staged_recipe.py` (Python 3 stdlib only, with a module
docstring that includes `Author: Edward Hartnett, Intelligent Data
Design, Inc.`):

- Usage: `python3 conda/make_staged_recipe.py VERSION SHA256 OUTDIR`.
- It writes `OUTDIR/recipes/nep-compress/recipe.yaml` and copies
  `build.sh` (keeping its mode).
- In the copy it replaces:
  - the single line `  version: "1.2.0.dev0"` with
    `  version: "VERSION"`;
  - the text from `# BEGIN source` through `# END source` (inclusive)
    with:

    ```yaml
    source:
      url: https://github.com/captainkirk99/nep-compress/archive/refs/tags/v${{ version }}.tar.gz
      sha256: SHA256
    ```
- It exits non-zero with a message if either marker, or the version
  line, is not found exactly once, or if `SHA256` is not 64 hex
  characters.

### 3. CI (`.github/workflows/conda.yml`)

```yaml
name: Conda package

on:
  push:
  pull_request:
  workflow_dispatch:

jobs:
  conda:
    runs-on: ubuntu-latest
    name: conda
    steps:
      - uses: actions/checkout@v4

      - name: Fetch conda-forge pinnings
        run: |
          set -euo pipefail
          curl -sSfL -o "${RUNNER_TEMP}/conda_build_config.yaml" \
            https://raw.githubusercontent.com/conda-forge/conda-forge-pinning-feedstock/main/recipe/conda_build_config.yaml

      - name: Build and test the recipe
        uses: prefix-dev/rattler-build-action@v0.2.39
        with:
          recipe-path: conda/recipe/recipe.yaml
          build-args: >-
            -m ${{ runner.temp }}/conda_build_config.yaml
            --output-dir ${{ runner.temp }}/conda-out
          upload-artifact: false

      - uses: mamba-org/setup-micromamba@v2
        with:
          environment-name: lint
          create-args: conda-smithy
          init-shell: bash

      - name: Lint the staged-recipes copy
        shell: bash -el {0}
        run: |
          set -euo pipefail
          python3 conda/make_staged_recipe.py 1.1.0 \
            1f55bf23d6fb6552c14d868416f71c194843f5d7c011d7571fedfd64a2a45e1e \
            "${RUNNER_TEMP}/staged"
          conda-smithy recipe-lint --conda-forge "${RUNNER_TEMP}/staged/recipes/nep-compress"

      - name: Upload package
        uses: actions/upload-artifact@v4
        with:
          name: nep-compress-conda
          path: ${{ runner.temp }}/conda-out/**/*.conda
```

Tricky cases:
- `ci.yml` and `spack.yml` are unchanged.
- If `rattler-build-action` v0.2.39 does not accept `build-args` or
  `upload-artifact` under those names, read the action's `action.yml`
  at that tag and use its real input names. Do not drop the `-m`
  pinnings.
- The pinnings file sets `channel_sources: conda-forge`, and
  rattler-build 0.79 errors when `channels` (`-c`) and
  `channel_sources` are both set, so `-c conda-forge` is left out.
- Lint findings that are hints only (not errors) do not fail the
  step. `recipe-lint` exits non-zero only on errors.
- When v1.2.0 is tagged, this workflow's `1.1.0` / sha256 arguments
  stay as they are until the feedstock exists. After that, this lint
  step is removed (item 5 of `docs/conda-plan.md`).

  (nep-compress is Unix-only).

  the recipe moves the file.
