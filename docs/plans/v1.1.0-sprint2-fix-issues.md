# V1.1.0 Sprint 2: Fix Issues

Source: `docs/roadmap.md`, "V1.1.0 - Documentation / Sprint 2".

## Goal

Fix GitHub issues #3, #4 and #5. Afterwards nep-compress no longer
exports symbols that clash with NetCDF-C. `nc_inq_var_lz4` correctly and
safely finds LZ4 anywhere in a variable's filter pipeline. LZ4 and BZIP2
report the same error codes as NetCDF-C's own filter wrappers. Every
test loads exactly the plugin it is meant to test. The documentation from
Sprint 1 describes the new behavior, and CI shows that the overflow is
gone and that the right LZ4 plugin is loaded.

## Decisions

| Topic | Decision |
| --- | --- |
| #3 duplicate bzip2 symbols | Remove the C `nc_def_var_bzip2` and `nc_inq_var_bzip2` from `libnepcompress` and use NetCDF-C's (always present since 4.9.0; the minimum is 4.10.1). Keep the Fortran `nf90_def_var_bzip2` and `nf90_inq_var_bzip2`, bound to NetCDF-C's symbols. Keep `NEPCOMPRESS_BUILD_BZIP2` to gate the Fortran BZIP2 API, the BZIP2 tests and the configure probe. (Ed: 1a) |
| LZ4 error semantics | `nc_def_var_lz4` follows NetCDF-C's `nc_def_var_bzip2`. It checks `nc_inq_filter_avail` first and returns `NC_ENOFILTER` if the plugin is missing, then returns `NC_EINVAL` for a level outside 1-9. Nothing is printed to stdout. `nc_inq_var_lz4` does **not** require the plugin, so metadata stays readable without it. (Ed: 2a) |
| #4 inquiry bug | `nc_inq_var_lz4` looks up `LZ4_ID` with `nc_inq_var_filter_info` and reads the parameter count before reading any parameters. It never calls `nc_inq_var_filter`. |
| #5 duplicate providers | No configure-time scanner. Each test's `HDF5_PLUGIN_PATH` contains only the directory for the filter it tests. The README tells users to use a BZIP2 directory with exactly one ID 307 provider and no ID 32004 provider, and shows how to make one on the development machine. (Ed: 3c) |
| Test strategy | Add #4 regression tests, a Linux `dl_iterate_phdr` check that the loaded `libh5lz4` comes from `build/plugin`, a check that `libnepcompress` exports no bzip2 symbols, and a C-only AddressSanitizer CI job. (Ed: 4a) |
| ABI / release | Keep `SOVERSION 1`. Document the change in `docs/compression.md` and in the v1.1.0 GitHub release notes. On ELF, existing binaries resolve the bzip2 symbols to libnetcdf's. (Ed: 5a) |

### 2. LZ4 define semantics

Replace `nc_def_var_lz4` in `src/nep_compress.c` with:

```c
int
nc_def_var_lz4(int ncid, int varid, int level)
{
    unsigned int value;
    int ret;

    if ((ret = nc_inq_filter_avail(ncid, LZ4_ID)))
        return ret;
    if (level < 1 || level > 9)
        return NC_EINVAL;
    value = (unsigned int)level;
    return nc_def_var_filter(ncid, varid, LZ4_ID, 1, &value);
}
```

Header doc: returns `NC_NOERR`, `NC_ENOFILTER` if the LZ4 plugin is
unavailable (checked before the level), `NC_EINVAL` for an invalid
level, or another NetCDF error. Mirror this in `nf90_def_var_lz4`
(`NF90_ENOFILTER`, `NF90_EINVAL`).

### 3. LZ4 inquiry (#4)

Replace `nc_inq_var_lz4` with:

```c
int
nc_inq_var_lz4(int ncid, int varid, int *lz4p, int *levelp)
{
    size_t nparams;
    unsigned int level;
    int ret;

    if (lz4p)
        *lz4p = 0;
    ret = nc_inq_var_filter_info(ncid, varid, LZ4_ID, &nparams, NULL);
    if (ret == NC_ENOFILTER)
        return NC_NOERR;
    if (ret)
        return ret;
    if (lz4p)
        *lz4p = 1;
    if (nparams != 1)
        return NC_EFILTER;
    if ((ret = nc_inq_var_filter_info(ncid, varid, LZ4_ID, &nparams, &level)))
        return ret;
    if (levelp)
        *levelp = (int)level;
    return NC_NOERR;
}
```

This contract matches NetCDF-C's `nc_inq_var_bzip2`, except that no
plugin is required. Document it in the header and in `nf90_inq_var_lz4`:

- It searches the whole filter pipeline, so LZ4 is found whatever its
  position.
- `*lz4p` is 1 if LZ4 is present.
- `*levelp` is written only when LZ4 is present with exactly one
  parameter.
- It returns `NC_EFILTER` (with `*lz4p = 1`) if LZ4 has a parameter
  count other than 1.
- It does not need the LZ4 plugin.
- It returns another NetCDF error, for example for a bad ID or a
  non-netCDF-4 file.

NetCDF-C logs a warning when the ID is not found. That is expected and
needs no handling.

6. **Docs:**

   ```sh
   cmake -DNEPC_OUTPUT_DIR=build/docs -DNEPC_WARN_AS_ERROR=FAIL_ON_WARNINGS -P docs/build_docs.cmake
   ```

   It must report zero warnings. Then run `grep -rn "EFILTER"` over
   `include fsrc docs README.md`. The only hits left should be the
   parameter-count descriptions.
7. Install and consumer: `cmake --install build-s2 --prefix build-s2/stage`,
   then build and run `test/consumer` as in `ci.yml`.
8. **CI:** all four matrix jobs (`lz4-c`, `bzip2-fortran`,
   `both-fortran`, `lz4-c-asan`) and `docs` pass on the PR.
