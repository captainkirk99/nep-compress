Detailed Description

Fortran module for LZ4, BZIP2 and JPEG-LS compression of NetCDF-4 variables.

These wrappers call the C functions declared in nep_compress.h and netcdf_filter.h. As usual in the NetCDF Fortran API, varid is 1-based; the wrappers subtract 1 before calling the C API.

Define BZIP2 compression on a NetCDF-4 variable.

Must be called in define mode, before data is written. Applying the filter forces chunked storage for the variable. An external HDF5 plugin that implements filter ID 307 must be available on HDF5_PLUGIN_PATH.

Parameters
ncidNetCDF file ID.
varidVariable ID (1-based, as in the NetCDF Fortran API).
levelBZIP2 compression level, 1 to 9 (block sizes of 100-900 KB).
Returns
NetCDF error code: NF90_NOERR on success, NF90_ENOFILTER if the BZIP2 filter plugin is unavailable (checked before the level), NF90_EINVAL for an invalid level, or another NetCDF error.

Calls NetCDF-C's nc_def_var_bzip2().

Define JPEG-LS compression on a NetCDF-4 variable.

Must be called in define mode, before data is written. The variable must be of type NF90_BYTE, NF90_UBYTE, NF90_SHORT or NF90_USHORT, and its rank must be 2 or 3. If the variable is not chunked yet, NetCDF-C's default chunk sizes are applied first. The resulting chunks must satisfy the plugin's requirements: in rank 3 the first chunk dimension is the number of image components and must be 1-4, the last two chunk dimensions are each at most 65535, and there must be at least 16 pixels per chunk. Changing the chunking after this call to a shape outside these limits makes HDF5 store the data uncompressed without an error. An external HDF5 plugin that implements filter ID 32018 (EUMETSAT fcidecomp or hdf5plugin) must be available on HDF5_PLUGIN_PATH.

Parameters
ncidNetCDF file ID.
varidVariable ID (1-based, as in the NetCDF Fortran API).
nearJPEG-LS near-lossless bound: 0 for lossless; 1-127 (1-byte types) or 1-255 (2-byte types) for near-lossless (lossy) compression, where every decoded value is within near of the original.
Returns
NetCDF error code: NF90_NOERR on success, NF90_ENOFILTER if the JPEG-LS filter plugin is unavailable (checked first), NF90_EBADTYPE for an unsupported type, NF90_EINVAL for a bad rank, near or chunk shape, or another NetCDF error.

Calls nc_def_var_jpegls().

Inquire whether JPEG-LS compression is in use on a NetCDF-4 variable.

The whole filter pipeline is searched, so filter 32018 is found whatever its position. The JPEG-LS HDF5 plugin does not need to be available.

nearRequired output argument; set to the JPEG-LS near-lossless bound stored with the filter when 32018 is present with 0, 9 or 13 parameters.
Returns

Inquire whether LZ4 compression is in use on a NetCDF-4 variable.

The whole filter pipeline is searched, so LZ4 is found whatever its position. The LZ4 HDF5 plugin does not need to be available.

Parameters
ncidNetCDF file ID.
varidVariable ID (1-based).
hasRequired output argument; set to 1 when the variable uses the LZ4 filter and 0 otherwise.
levelRequired output argument; set to the LZ4 acceleration level decoded from the encoder selector. For a one-parameter filter (written by nep-compress 1.1.0 and earlier, or by other tools as a block size), the stored value is returned unchanged.
Returns
NetCDF error code: NF90_NOERR on success, NF90_EFILTER (with has set to 1) if the LZ4 filter has a parameter count other than 1 or 2, an LZ4HC encoder selector, or an acceleration above 9, or another NetCDF error.
